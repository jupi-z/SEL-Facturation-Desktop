## Modifications de cet incrément

- USD est présenté comme devise principale et valeur par défaut des tarifs, kits, ligne de communication et profils de devises. CDF reste disponible ; aucune devise libre n’est saisissable.
- Le taux de change démarre de USD vers CDF et refuse la même devise comme source et cible.
- La devise d’une vente solaire vient du produit approuvé sélectionné ; le formulaire ne permet pas de la modifier indépendamment.
- Le catalogue solaire est formulé comme un catalogue de kits vendables après approbation. « Approuvé · vendable » n’affirme pas un niveau de stock. Aucun stock n’est ajouté.
- La vente demande le mode comptant ou échelonné. Le comptant ouvre ensuite l’encaissement avec le montant et la créance préremplis ; le paiement échelonné conduit au parcours de contrat. Le tarif reste celui du produit approuvé.
- Pour les nouvelles versions de produit, l’identification d’une version antérieure du même SKU/type/devise est automatique lorsque les dates se chevauchent ; l’approbation SEL conserve une référence de décision obligatoire.
- Les métriques d’administration reflètent la rubrique de catalogue consultée plutôt que le total de tous les référentiels.
- Les sélecteurs et libellés du script Playwright ont été alignés avec les parcours d’administration actuels. Des assertions couvrent les valeurs USD/CDF par défaut et les options de devise.

## Correctif fiabilité des interfaces — 11 novembre 2026

### Cause exacte du message « Données indisponibles »

Le serveur Rust expose bien `GET /v1/admin/catalog/communication-charge` et `GET /v1/admin/configuration/readiness`. Le client Tauri Windows applique une liste locale de routes autorisées avant d’envoyer une requête centrale ; cette liste omettait ces deux chemins. Le pont natif rejetait donc les appels avant qu’ils n’atteignent le serveur. Le chargement de l’administration utilisait en outre des setters qui remplaçaient par des tableaux vides les sections dont la requête échouait, ce qui effaçait aussi les dernières données encore visibles.

### Corrections

- Autoriser explicitement les lectures du catalogue « Ligne de communication » et du diagnostic de configuration, ainsi que la création et l’approbation de versions de la ligne de communication. Le pont continue de refuser les méthodes et actions non prévues (notamment POST sur le diagnostic et révocation de la ligne de communication).
- En cas d’échec partiel, conserver les dernières données chargées et afficher une alerte indiquant quelles sections sont à actualiser ; seules les données d’une session explicitement fermée sont effacées.
- Étendre les tests de contrat Rust, les tests statiques/React et le scénario Playwright synthétique pour couvrir les nouvelles routes, les méthodes refusées et la conservation des données si une section échoue.
- Aligner le parcours de recette admin avec le comportement actuel : confirmation explicite avant abandon d’un formulaire modifié et choix explicite du catalogue Tarif après retour dans les référentiels.
